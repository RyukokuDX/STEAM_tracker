# 物品登録フォーム — 実装仕様書

> 本書は現行実装（`stuffForm/index.html` / `stuffForm/GAS/code.js`）に準拠する。最終更新: 2026-11-05
>
> スプレッドシートの列定義は `docs/SPREAD_SHEET_REQUIREMENTS.md` を正とし、本書では参照のみ行う。

このドキュメントはフォーム実装者・テスター向けの仕様書です。フォームの入力項目、検証ルール、スプレッドシートへの記録仕様、通知、受け入れ基準および簡易テストケースを定義します。

---

## 1. 前提

- フォーム画面は静的 HTML（`stuffForm/index.html`）で、GitHub Pages で公開する。送信先の GAS Web アプリ URL は GitHub Actions の Secret `STUFF_GAS_URL` から埋め込む。
- 利用者は館内に掲示された QR コードからフォームを開く。
- 画像は Google Drive（スクリプトプロパティ `driveFolder_ID` のフォルダ）に保存し、ファイル ID をスプレッドシートに記録する。

---

## 2. 利用規約への同意

- 利用規約を最後までスクロールし、第 6 条の確認チェックを入れ、第 6 条に関するクイズに正解すると「同意」ボタンが有効になる。

---

## 3. フォーム項目

| ラベル | 送信キー | 必須 | 検証 / 制約 |
| --- | --- | :--: | --- |
| 氏名 | name | 必須 | 前後空白を除去して空欄不可、50 文字以内 |
| 団体名（任意） | organization | 任意 | なし |
| 写真を添付 | photo | 必須 | ブラウザで長辺 1280px・JPEG（品質 0.85）に圧縮してアップロード。サーバーは JPEG/PNG/WebP のみ受け付ける |
| メールアドレス | email | 必須 | 形式チェック、`@mail.ryukoku.ac.jp` のみ（大文字小文字は区別しない） |
| 明け渡し日 | date | 必須 | `YYYY-MM-DD`、今日以降かつ年度末（3 月 31 日）まで |

検証はフロントエンドとサーバー（`submitForm`）の両方で行う。

---

## 4. スプレッドシートへの記録仕様

- 記録先は items シート（無ければ作成し、空ならヘッダー行を追加する）。
- 同時送信に備え ScriptLock（最大 30 秒待機）で排他制御する。

| 列 | カラム名 | 記録内容 |
|:---:|:---|:---|
| A | registered_at | 送信時刻 |
| B | email | 入力されたメールアドレス |
| C | name | 氏名 |
| D | organization | 団体名（未入力なら空欄） |
| E | photo_file_id | Drive ファイル ID |
| F | handover_on | 明け渡し日（`yyyy/MM/dd`） |
| G | days_until_handover | 空欄（現行実装では使用しない。`docs/SPREAD_SHEET_REQUIREMENTS.md` 参照） |
| H | status | `active` |
| I | admin_note | 空欄 |

---

## 5. 通知

### 確認メール（登録者向け）

- 件名: 「【STEAMコモンズ】物品登録完了のお知らせ」
- 本文: 氏名・団体名・明け渡し日、明け渡し日までの撤去のお願い、延長申請フォームの URL（スクリプトプロパティ `EXTEND_FORM_URL` 設定時）、心当たりがない場合の案内、STEAMコモンズの所在地。
- 送信に失敗した場合は、登録自体は完了していることと失敗理由をフォームに表示する。

### 管理者向け LINE 通知

- `line_bot` の Web アプリ（スクリプトプロパティ `LINE_BOT_NOTIFY_URL`）へ `notifyRegistration` を POST し、管理者に写真・氏名・団体名・明け渡し日を通知する。
- 失敗した場合は、送信完了メッセージに「管理者向けLINE通知に失敗しました」と付記する。

### リマインド

- 明け渡し 3 日前・当日のリマインドは `line_bot` が行う（`docs/SPECIFICATIONS.md` §3(2)）。

---

## 6. 受け入れ基準（Acceptance Criteria）

1. 規約の同意（スクロール・確認チェック・クイズ正解）なしに入力画面へ進めないこと。
2. 必須項目（氏名・写真・メールアドレス・明け渡し日）が未入力で送信できないこと。
3. `@mail.ryukoku.ac.jp` 以外のメールアドレスはエラーになること。
4. 明け渡し日が過去日または年度末より後の場合、エラーになること。
5. 写真が Drive に保存され、E 列にファイル ID が記録されること。
6. 登録行の H 列が `active` になること。
7. 送信後、登録者に確認メール（延長申請フォームの URL を含む）が送信されること。
8. 送信後、管理者に明け渡し日を含む LINE 通知が届くこと。

---

## 7. テストケース（簡易）

- TC-01: 正常フロー — 全項目正常入力 → 送信成功、items に記録（status=active）、確認メール送信、管理者へ LINE 通知。
- TC-02: メール不正 — `invalid.email` → 形式エラー。
- TC-03: 学外ドメイン — `user@example.com` → ドメインエラー。
- TC-04: 過去日指定 — 明け渡し日を過去日に設定 → エラー。
- TC-05: 年度末超過 — 明け渡し日を翌年度の 4 月 1 日に設定 → エラー。
- TC-06: 画像形式 — GIF などを直接 POST → `uploadPhoto` がエラーを返す。

---

## 8. 運用上の注意

- 画像の保存期間・アクセス権・削除ポリシーを運用で明確にすること。
- スプレッドシートと各 GAS プロジェクトのタイムゾーンは東京（GMT+09:00）に設定すること。
