# 詳細仕様書

---

## 1. システム概要

本システムは、スチームコモンズにおける物品の登録・撤去・延長申請を自動で管理する。  
Googleフォーム、スプレッドシート、Gmail、LINE、Google Apps Script（GAS）を連携させて運用する。  
本仕様書では、要件定義書（REQUIREMENTS.md）で定められたビジネス要件を基に、具体的な実装仕様を定義する。

---

## 2. システム構成

| 区分 | 使用ツール | 機能概要 |
| :-- | :-- | :-- |
| 登録処理 | Googleフォーム / GAS | フォーム送信時に回答内容をスプレッドシートの管理シートへ記録する。 |
| データ管理 | Googleスプレッドシート | 登録データを一元管理。残り日数や状態を自動更新する。 |
| 日次処理 | GAS（時間主導トリガー） | 登録データの残り日数を更新し、必要に応じてリマインダーを送信する。 |
| リマインダー通知 | Gmail | 撤去予定日が近づいた利用者にメールを自動送信する。 |
| 年度末通知 | Gmail | 年度末が最終的な回収期限であることを全登録者に一斉送信する。 |
| 延長申請 | Googleフォーム | 利用者が撤去日の延長を申請するためのフォーム。 |
| 管理者通知 | LINE | 延長申請や撤去完了の報告を管理者へ通知する。 |
| アーカイブ処理 | GAS | 撤去完了済みのデータをアーカイブ用シートに自動で移動する。 |

## 3. 機能詳細仕様

### （1）物品登録機能

#### アクセス方法
- スチームコモンズ内に掲示された共通のQRコードをスマートフォンで読み取る
- QRコードはGoogle Formsの登録フォームURLにリンクしている

#### 入力項目
| 項目名 | データ型 | 必須/任意 | バリデーション | 備考 |
| :-- | :-- | :-- | :-- | :-- |
| メールアドレス | Email | 必須 | メール形式チェック | フォーム設定で自動取得 |
| 氏名 | Text | 必須 | 最大50文字 | - |
| 団体名 | Text | 必須 | 最大100文字 | - |
| 物品の写真 | File Upload | 必須 | 画像形式（JPG, PNG） | Google Driveに自動保存 |
| 明け渡し日 | Date | 必須 | 当日以降の日付、年度末以前 | 年度末が最終期限 |
| 規約への同意 | Checkbox | 必須 | チェック必須 | - |

#### 処理フロー（実装レベル）
1. 利用者がQRコードをスキャン
2. Google Formsが開く
3. 利用者が必要情報を入力
4. フォーム送信時、GASの`onFormSubmit`トリガーが発火
5. 回答内容をスプレッドシートの管理シートに記録
6. 写真はGoogle Driveに保存され、リンクを記録
7. 初期状態を「未完了」として設定
8. 登録者と管理者にGmailで通知を送信

#### 通知内容
**利用者宛**
- 件名：「物品登録完了のお知らせ」
- 本文：登録内容の確認、明け渡し日の確認、延長申請方法の案内

**管理者宛**
- 件名：「新規物品登録の通知」
- 本文：登録者情報、物品情報、写真リンク

### （3）延長申請機能

#### アクセス方法
- リマインダーメールに記載された延長申請フォームURLからアクセス
- Google Formsを使用

#### 入力項目
| 項目名 | データ型 | 必須/任意 | バリデーション | 備考 |
| :-- | :-- | :-- | :-- | :-- |
| メールアドレス | Email | 必須 | 登録時と同じアドレス | 自動取得 |
| 氏名 | Text | 必須 | - | 本人確認用 |
| 延長理由 | Long Text | 必須 | 最大500文字 | - |
| 希望延長期間 | Date | 必須 | 現在の明け渡し日より後、年度末以前 | - |

#### 処理フロー
1. 利用者が延長申請フォームに入力
2. フォーム送信
3. GASが延長申請を記録
4. 管理者にLINE通知を送信
5. 管理者が承認/却下を判断
6. 承認の場合、スプレッドシートの明け渡し日を更新

#### 制約条件
- 延長申請は複数回可能だが、最終期限（年度末）を超えることはできない
- 延長申請の承認は管理者の裁量による

### （4）撤去完了・アーカイブ機能

#### 撤去完了処理（手動）
1. 利用者が物品を撤去
2. 利用者が管理者に口頭で報告
3. 管理者が現地で撤去を確認
4. 管理者がスプレッドシートの「状態」列を「完了」に変更

#### アーカイブ処理（自動）
**トリガー**: 時間主導型（毎日指定時刻）

**処理内容**:
1. 管理シートから「状態」が「完了」の行を検出
2. アーカイブ用シートに行をコピー
3. コピー時に「確認日」（処理実行日）を追加
4. 「残り日数」「状態」列は削除
5. 管理シートから元の行を削除

**エラー処理**:
- アーカイブ失敗時は管理者にLINE通知

## 4. 処理仕様（内部処理）

### （1）登録処理（内部処理：`onFormSubmit`）
- 物品登録フォームの回答送信をトリガーに、GASで回答内容を取得しスプレッドシートに記録する。  
- スプレッドシートの列構成は「メールアドレス、氏名、団体名、写真リンク、撤去予定日、残り日数、状態」とする。  
- 写真はDrive上の共有リンクとして記録する。  
- 初期状態はすべて「未完了」として登録される。  

---

### （2）日次自動処理

#### 残り日数更新処理（内部処理：`updateRemainingDays`）
- 時間主導トリガーにより、毎日指定時刻に実行される。  
- 登録データの撤去予定日と現在日付との差を計算し、「残り日数」列に記録する。  
- 残り日数は「○日」または「今日まで」として表記する。  
- **この処理の内部で、残り日数が「3日」または「0日」の場合、`sendReminderEmails` を呼び出して個別通知を送信する。**

#### リマインダー送信処理（内部処理：`sendReminderEmails`）
- `updateRemainingDays` によって呼び出される。  
- 「残り日数」が **3日** または **0日** のデータを抽出し、登録者へGmailで通知を送信する。  
- 件名：「スチームコモンズの物品撤去日について」  
- 本文には、残り日数と延長申請フォームへのリンクを記載する。  

---

### （3）年度末一斉リマインダー処理（内部処理：`sendFinalReminderAll`）

- **目的**：年度末が最終的な回収期限であることを、全登録者に一斉通知する。  
- **実行トリガー**：時間主導トリガー（年度末直前の指定日、例：3月20日 10:00）  
- **送信内容**：  
  - 件名：「【重要】年度末の物品撤去について」  
  - 本文：「年度末が最終的な撤去期限であるため、未撤去の物品はこの日までに撤去してください。」  
- 宛先：管理シート上で「状態」が「未完了」の全登録者  
- 管理者にも同報通知を送信する。

---

### （4）撤去完了・アーカイブ処理

#### 管理者の撤去完了処理
- 利用者が物品を撤去した後、管理者に口頭で報告する。  
- 管理者はスプレッドシートの「状態」列を「完了」に変更することで撤去完了処理を実行する。  

#### アーカイブ処理（内部処理：`archiveCompletedItems`）
- 「状態」が「完了」となった行を検出し、同一スプレッドシート内の「アーカイブ用シート」に自動で移動する。  
- 移動後、元の管理シートから該当行を削除し、アーカイブ側には「確認日」を追記する。  
- **アーカイブ側では、「残り日数」と「状態」の列は削除し、主要情報のみを保持する。**  
- アーカイブは毎日自動実行（時間主導トリガー）または手動実行のどちらにも対応可能とする。

## 5. データ定義

### （1）Google Sheetsテーブル構造

#### 管理シート（シート名：「シート1」または「管理シート」）

| 列番号 | カラム名 | データ型 | 必須 | 説明 | 設定方法 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 1 | メールアドレス | String | ○ | 登録者のメールアドレス | フォームから自動取得 |
| 2 | 氏名 | String | ○ | 登録者の氏名 | フォーム入力 |
| 3 | 団体名 | String | ○ | 所属団体名 | フォーム入力 |
| 4 | 写真 | String (URL) | ○ | Google Drive上の写真リンク | フォームアップロード |
| 5 | 撤去予定日 | Date | ○ | 物品を撤去する予定日 | フォーム入力 |
| 6 | 残り日数 | String | - | 撤去予定日までの残り日数 | GASで自動計算 |
| 7 | 状態 | String | ○ | 「未完了」または「完了」 | 初期値「未完了」、管理者が変更 |

#### アーカイブ用シート（シート名：「アーカイブ」）

| 列番号 | カラム名 | データ型 | 必須 | 説明 | 設定方法 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 1 | メールアドレス | String | ○ | 登録者のメールアドレス | 管理シートからコピー |
| 2 | 氏名 | String | ○ | 登録者の氏名 | 管理シートからコピー |
| 3 | 団体名 | String | ○ | 所属団体名 | 管理シートからコピー |
| 4 | 写真 | String (URL) | ○ | Google Drive上の写真リンク | 管理シートからコピー |
| 5 | 撤去予定日 | Date | ○ | 物品を撤去した予定日 | 管理シートからコピー |
| 6 | 確認日 | Date | ○ | 管理者が撤去完了を確認した日 | アーカイブ時に自動設定 |

### （2）データバリデーション

#### 撤去予定日
- 入力範囲：当日以降、年度末（3月31日）以前
- フォーマット：YYYY-MM-DD
- エラー時：「撤去予定日は本日以降、年度末以前の日付を指定してください」

#### 状態
- 許可される値：「未完了」「完了」
- デフォルト値：「未完了」

#### 写真
- ファイル形式：JPG, PNG, GIF
- 最大ファイルサイズ：10MB
- エラー時：「画像ファイルは10MB以下のJPG、PNG、GIF形式でアップロードしてください」

## 10. エラー処理

- **日付形式エラー**：不正な形式はスキップし、ログに記録する。  
- **メール送信失敗**：送信失敗時はスプレッドシートに「送信失敗」と記録する。  
- **アーカイブ失敗**：行移動時にエラーが発生した場合、管理者にLINE通知を送信する。

## 11. 非機能要件

### （1）セキュリティ

#### データアクセス制御
- Google Sheetsは管理者と開発チームのみアクセス可能とする
- 利用者は自身の登録情報のみ閲覧可能（Google Formsの設定による）
- 機密情報（メールアドレス、氏名）は適切に保護する

#### 認証・認可
- Google Formsへのアクセスは学内メールアドレス（@mail.ryukoku.ac.jp）に制限
- GASの実行権限は管理者のみに付与

### （2）パフォーマンス

#### レスポンス時間
- フォーム送信から登録完了通知まで：5秒以内
- 日次処理の実行時間：最大10分（登録件数による）

#### スケーラビリティ
- 想定登録件数：年間500件程度
- Google Sheetsの行数上限：10,000行（十分な余裕あり）

### （3）可用性

#### 稼働時間
- システムは24時間365日稼働
- Google Workspaceのサービスレベルに依存

#### バックアップ
- Google Sheetsは自動バージョン管理により過去データの復元が可能
- 重要なタイミング（年度末など）で手動バックアップを推奨

### （4）保守性

#### ログ記録
- GASの実行ログは自動的に記録される
- エラー発生時は管理者に通知

#### ドキュメント
- 本仕様書と要件定義書で仕様を明確化
- コード内にコメントを適宜記載
