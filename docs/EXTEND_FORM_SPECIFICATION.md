# 延長申請フォーム仕様書

> 本書は現行実装（`extend_form/index.html` / `extend_form/GAS/code.js`）に準拠する。最終更新: 2026-11-12

## 1. 概要
本仕様書では、スチームコモンズ物品管理システムにおける延長申請フォームの動作仕様を定義する。延長申請フォームは、利用者が明け渡し日の延長を申請するための Web フォームである。
画面は静的 HTML（`extend_form/index.html`）で GitHub Pages に公開し、処理は GAS Web アプリ（`extend_form/GAS/code.js`）が行う。送信先 URL は GitHub Actions の Secret `EXTEND_GAS_URL` から埋め込む。

## 2. フォームへの導線
- 登録完了の確認メール（`stuffForm`、スクリプトプロパティ `EXTEND_FORM_URL`）
- 明け渡し 3 日前・当日のリマインドメール（`line_bot`、スクリプトプロパティ `EXTEND_FORM_URL`）

## 3. 画面と入力項目
1. ログイン画面
   - 学籍番号を入力する。`{学籍番号}@mail.ryukoku.ac.jp` をメールアドレスとして、items から物品を検索する。
   - 対象は、メールアドレスが一致し（大文字小文字は区別しない）status が `active` の物品のみ。
2. 申請画面
   - 物品ごとに「{氏名}（{団体名}）」、現在の明け渡し日、写真、延長希望日の入力欄を表示する。入力欄の初期値は現在の明け渡し日。
   - 延長したい物品の日付だけを変更して送信する。日付を変更していない物品は申請されない。
   - 1 件も変更していない場合は「延長したい物品の日付を変更してください。」と表示し、送信しない。
3. 完了画面
   - 「申請内容を確認後、メールにて通知いたします。」と表示する。
   - 一部の物品が申請できなかった場合は、その物品と理由をあわせて表示する。

## 4. 日付入力の制限
- カレンダーウィジェットで選択する。
- 延長できるのは「明日以降かつ現在の明け渡し日より後」から「現在の明け渡し日が属する年度の末日（3 月 31 日）」まで。年度末を越える延長はできない（`docs/REQUIREMENTS.md` の設置期間の原則）。
- 範囲はサーバー（GAS）が日本時間で計算して画面に渡し、画面とサーバーの両方で検証する。サーバー側では次の申請を受け付けない。
  - 日付形式が YYYY-MM-DD でない、または実在しない日付（2027-02-30 など）
  - 現在の明け渡し日と同じ
  - 上記の範囲外
- 次の物品は一覧に理由を表示し、入力不可にする（申請できる物品が 1 つもなければ「申請する」ボタンも押せない）。
  - 範囲が空になる物品（明け渡し日が年度末、または年度末を過ぎている）：「年度末（{日付}）を過ぎる延長はできません。期限までに撤去するか、STEAMコモンズの管理者にご相談ください」
  - 登録日時（A 列）または明け渡し日（F 列）が読み取れない物品：「…が不明なため申請できません。STEAMコモンズの管理者にお問い合わせください」

## 5. 物品の特定方法
- 物品は「メールアドレス（大文字小文字は区別しない）＋登録日時（registered_at、秒単位）」の組み合わせで特定する。
- シートの行番号は、ダッシュボードでのアーカイブ・削除・復元で変わるため、識別子として使わない。
- 申請の受付時と、管理者が許可/却下を押した時点のそれぞれで、シートを検索し直して対象行を決める。

## 6. 管理者への通知と承認
- 送信すると、申請された物品ごとに管理者へ LINE を送る（「延長申請」、「{氏名}（{団体名}）」、「明け渡し日：{現在の明け渡し日}」、「希望延長日：{日付}」、「許可」「却下」ボタン。日付は yyyy/MM/dd 表記）。
- ボタンの postback データには、action・メールアドレス・登録日時（秒）・申請時点の明け渡し日（cur）・希望延長日（date）・署名（sig）を入れる（許可・却下とも同じ項目）（例: `action=approve&email=...&reg=1787571600&cur=2026-12-17&date=2027-01-15&sig=...`、約 140 文字）。
- 署名は、postback の内容をスクリプトプロパティ `POSTBACK_SIGNING_SECRET` の鍵で HMAC-SHA256 したもの。GAS の doPost ではリクエストヘッダーを読めず LINE 標準の署名検証ができないため、その代わりとして使う。鍵は `setupPostbackSecret` を一度実行して作成する。鍵が無い間は延長申請を受け付けない。
- 署名が一致しない操作（偽装・改ざんの可能性）は、何も処理せずログにだけ記録する。
- ボタン操作は LINE Webhook（`extend_form` の `doPost`）で受け取る。スクリプトプロパティ `USER_ID` 以外からのイベントは無視する。
- Webhook の送信元確認として、LINE Developers に登録する Webhook URL の末尾に `?token={LINE_WEBHOOK_TOKEN}` を付け、URL のトークンがスクリプトプロパティ `LINE_WEBHOOK_TOKEN` と一致しない Webhook は処理しない（ログにだけ記録する）。トークンは `setupWebhookToken` を一度実行して作成する。未設定の間は Webhook を受け付けない。
- 許可した場合: items の handover_on を希望延長日に更新し、利用者に「STEAMコモンズ 延長申請許可通知」メールを送り、管理者に「{氏名}（{団体名}）の延長申請を {日付} まで許可しました。」と LINE で送る。
- 却下した場合: 利用者に「STEAMコモンズ 延長申請却下通知」メールを送り、管理者に「{氏名}（{団体名}）の延長申請を却下しました。」と LINE で送る。
- 利用者へのメール送信に失敗した場合は、管理者への LINE に失敗理由を付記する。
- 次の場合は更新もメール送信もせず、管理者に LINE で理由を知らせる。
  - 対象の物品が見つからない（アーカイブ・削除済み、またはメールアドレス・登録日時が変更された）
  - 同じメールアドレス・登録日時の物品が複数ある
  - 対象の物品の status が `active` でない
  - 署名の無い旧形式のボタン（本仕様への変更前に送られた申請）。利用者に再申請を依頼する
- 許可・却下を処理した申請は、スクリプトプロパティ `EXTENSION_DECISIONS` に記録する（最初の記録時に自動で作成される）。同じ申請のボタンがもう一度押された場合は処理せず、「すでに許可（却下）済みです」と LINE で知らせる（二度押しや、許可後の却下・却下後の許可を防ぐ）。
  - 申請は「物品（メールアドレス＋登録日時）＋申請時点の明け渡し日＋希望延長日」で区別する。
  - 希望延長日の当日以降は、その申請の許可・却下はできない（「希望延長日を過ぎているため処理できません」と LINE で知らせる）。そのため、希望延長日を過ぎた申請の記録は自動で削除する。
- 記録が無い場合でも、明け渡し日がすでに希望延長日になっているときは、メールを再送せず「すでに更新済み」と LINE で知らせる。
- 許可・却下を押した時点の明け渡し日が、申請時点（cur）と違う場合（別の申請を許可済みなど）は処理せず、LINE で知らせる。
- 同時に押された場合に二重に処理しないよう、許可・却下の処理は排他制御（ScriptLock）の中で行う。
- 許可を押した時点で希望延長日が範囲外になっている場合（許可が遅れて希望日が過ぎたなど）は許可せず、利用者に再申請してもらうよう LINE で知らせる。

## 7. 利用者への通知
- 申請受付時点ではメールを送らない。
- 管理者の許可・却下時にメールで結果を通知する。

## 8. 申請内容の保存
- 申請内容そのものは保存しない。管理者が許可した場合のみ、items の handover_on 列に反映される。
